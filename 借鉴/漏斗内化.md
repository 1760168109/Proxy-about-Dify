# 漏斗内化

> **定位**：面向“多个参考来源 → 一个目标项目”的轻量通用方案。
>
> **核心**：先以低成本概览扫描定位高价值机制，再把精读、双端核查与反证资源集中于少数选题。内化单位是“问题／机制”，不是仓库；单一来源可以贡献多个选题，也可以在概览后不进入精研。

## 一、三份正式产物

整个流程只保留三份正式文件：

```text
01-概览与选题.md    来源地形、候选机制、选择/旁证/排除及理由
02-精研与映射.md    入选机制的来源证据、目标事实、净变化与反证
03-综合内化方案.md  跨机制归并、裁决、实施方向、验证与回滚
```

过程搜索、临时索引、标题树和试读笔记默认留在对话上下文；确需落盘时标为临时文件，阶段结束前蒸馏或清退。

## 二、漏斗

```text
项目镜面
  ↓
概览扫描：宽读、浅入、建立来源地图
  ↓ 选择门
精确内化：窄读、深证、双端映射
  ↓ 独立复核（改同一文件，不增产物）
综合融会：按目标不变量归并
  ↓
唯一方案；实施另行启动
```

### 效益原则

1. 概览成本由“能否可靠选题”决定，不由仓库文件总数决定。
2. 精研成本只投向通过选择门的机制，不为仓库完整性付费。
3. 深度随决策影响上升：只作旁证的来源不必获得与主证据相同的阅读量。
4. 证据达到足以支持“采用／保持／排除／待核”时停止，不追求知道仓库的一切。
5. 文档数量不随仓库数增长；来源与选题都在三份文件内用稳定 ID 追溯。

## 三、项目镜面

每个目标项目只需一份镜面文件，包含：

```markdown
# {目标项目} · 借鉴镜面

## 项目定位与北极星
## 当前主链与明确不是
## 改善量纲
## 不变量与保护机制
## 本轮查找镜头
## 事实源、默认不读与外部边界
## 参考来源清单与最小身份
## 三份产物路径
```

镜面负责提供判断尺度，不预判任何来源必然有用。参考来源中的异质机制若无法被现有镜头安放，概览中登记“照不动”，不能强行归类或静默丢弃。

### 最小来源身份与清退

一次性个人研究不要求保存 ZIP、下载日期、tag、commit 或校验值。默认只保留：

- 一个稳定来源 ID 与仓库名称；
- GitHub 页面或其他来源入口（已知时）；
- 研究期间的本地目录；
- 精研卡中真正引用过的相对路径、代码符号与测试名。

这些信息足以说明判断来自哪里，也足以在极少数需要重访时重新下载。只有结论将用于高风险删除、公开审计或严格复现实验时，才额外记录 tag、commit 或压缩包校验值。

`03-综合内化方案.md` 定稿后，参考源码可以整体清退；三份结果文件与项目镜面继续保留。若马上要实施一项高风险改造，可暂留被该方案直接引用的少数来源，直至实施与验证结束。

## 四、阶段一 · 概览扫描

### 目的

概览不生成仓库报告，只回答：

- 这个仓库真正解决什么问题；
- 与本轮目标相交的机制在哪里；
- 哪些部分值得精研、只需旁证或应排除；
- 精研必须读取哪些路径、符号和测试。

### 读取顺序

每个来源按同一顺序扫描：

1. 仓库内代理说明、README、架构/配置文档与 manifest；
2. 顶层目录、主要包与测试分布；
3. 与项目镜头相交的入口、接口、类型、注册表或状态对象；
4. 候选机制的 1–2 个实现锚及相邻测试；
5. 只有地图仍无法判断时，才继续向下读取。

默认不逐文件通读，不展开与本轮无关的 UI、营销、翻译、管理后台、构建物和依赖目录。

### 来源概览卡

```markdown
### S-{编号} · {仓库名}

- 来源：{稳定 ID / 仓库名 / URL（若有） / 当前本地目录}
- 一句话定位：
- 主控制链：{3–7 步}
- 与目标交点：
- 候选机制：{名称 + 首选锚点}
- 可能收益：{作用于哪个改善量纲}
- 主要代价/错配：
- 证据可达性：清楚 / 尚需定位 / 仅有宣称
- 建议：精研 / 旁证 / 排除
- 理由与未读边界：
```

### 选择门

一个机制进入精研，至少同时满足：

1. **有目标问题**：能对应一个目标不变量、已知负担或明确的“照不动”问题；
2. **有净收益假设**：可能减少至少一个量纲的负担，且新增代价尚未明显压倒收益；
3. **有证据入口**：能定位实现、测试、配置或明确失败路径，不只依赖 README 宣称；
4. **有可迁移边界**：不必搬入整个平台才能取得该机制；
5. **值得决策**：进一步研究可能改变“采用、保持、排除或补证”的结论。

结果分三类：

| 结果 | 含义 | 后续成本 |
| --- | --- | --- |
| 精研 | 有目标交点、有证据入口、可能改变决策 | 进入阶段二 |
| 旁证 | 能补强或反驳另一选题，但不独立成题 | 随主选题定点读取 |
| 排除 | 不适用、代价显著过高、目标已更适配或证据不可达 | 只保留一句理由 |

概览结束后先确定**精研题目**，再按题目归集来源。不得把“来源数量”机械转换成同等数量的精研题目。

## 五、阶段二 · 精确内化

### 单位

精研单位是一个可裁断的问题，例如：

- 请求 IR 是否能消除重复扫描与事实分歧；
- 显式 stream state 是否能收敛终态处理；
- 按字节与请求性质治理日志能否保留诊断而降低磁盘占用。

一个题目可使用一个主来源、若干旁证来源；同一来源也可服务多个题目。

### 双端读取顺序

1. 先读主来源候选锚点及其失败路径，形成来源事实；
2. 再读目标项目对应控制链，形成目标事实与已有保护；
3. 最后比较机制，不从“参考实现更短”直接推出目标应改；
4. 需要时读取旁证来源，用于反例、替代形态或代价校准；
5. 证据已足以裁断时停止，不扩成完整仓库调研。

### 精研卡

所有卡写入同一份 `02-精研与映射.md`：

```markdown
## T-{编号} · {精研问题}

### 暂定结论
采用 / 合并精简 / 等价替换候选 / 保持现状 / 排除 / 待外部证据

### 来源事实
- 主来源与锚点：
- 机制链与强制位置：
- 成立条件：
- 消除的复杂度：
- 引入的复杂度：
- 旁证与反例：

### 目标事实
- 当前链与锚点：
- 已有保护及所防故障：
- 当前负担：
- 当前证据等级：

### 映射判断
- 两端是否同类：
- 推理桥：
- 拟移除：
- 新增代价：
- 净变化（分量纲）：
- 明确不搬：

### 验证与边界
- 怎样证明等价或改善：
- 当前仍不能证明：
- 需要柳生裁什么：
- 失败时回到哪里：
```

### 保护机制门

凡涉及删除、替换、合并或短路现有逻辑，须先写清：

```text
触发条件 → 所防故障 → 外部行为 → 当前实现 → 验证锚点 → 等价替代 → 未证部分
```

缺任一承重环节时，不得得出删除结论，只能保持、收窄或转为待证。

### 自适应停止

出现以下任一状态即可结束该题精研：

- 已有双端锚点，净变化和故障边界清楚，足以进入综合；
- 已证明目标现状更适配，继续读不会改变排除结论；
- 真正差异取决于外部运行事实，继续静态阅读无增益；
- 迁移必须搬入显著超出目标边界的平台层，净收益假设已失败；
- 来源本身缺少可核证实现，无法从宣称推进。

## 六、阶段三 · 独立复核

复核使用新鲜上下文，直接修订同一份 `02-精研与映射.md`，不另产核查报告。

逐题检查三层：

1. **事实偏差**：来源和目标事实是否被锚点支持；
2. **提取偏差**：机制链、数字、枚举、状态与失败边界是否读错；
3. **结构缺陷**：两端是否真的同类，是否隐藏新增复杂度、重复计重或以偏概全。

复核结果只在卡内留下最终结论、必要收窄与仍存异议；过程争论不另立文件。

## 七、阶段四 · 综合融会

综合只读取项目镜面、`01` 与已复核的 `02`，按目标不变量而非仓库归并：

- 重合机制合并，保留来源不同侧面；
- 同主题但失败域不同者分开；
- 多来源照见同一目标锚点不重复计重；
- 跨量纲收益与代价分别呈现，不压成伪总分；
- 产品/架构取舍交柳生裁，外部事实进入证据门；
- 方案只包含已精研题目，不夹带扫描中顺手发现的普通 TODO。

`03-综合内化方案.md`至少包含：

```markdown
# {目标项目} · 综合内化方案

## 当前基线与不变量
## 精研结论总览
## 采用、保持与排除
## 净变化与保护边界
## 柳生裁决
## 外部证据门
## 实施顺序与独立支线
## 验证、退出与回滚
## 来源追溯与未核验边界
```

柳生裁决写回同一文件后定稿。定稿即停止；实施另行启动。

## 八、共同证据纪律

- 来源事实、目标事实、分析判断、外部事实和柳生裁决须能区分；
- 证据等级使用：`未核验 < 静态实现 < 自动测试 < 本地运行 < 外部联调`；
- 实现存在不等于路径已运行，生成响应不等于客户端已消费；
- Stars、来源数量和技术栈相似度只用于发现，不用于证明；
- 概览可以宽，正式结论必须窄而有锚；
- 无高价值机制时允许单一来源零产出，也允许整轮结论是保持现状。

## 九、适用与不适用

适合：目标明确、来源较多、希望在成本可控下寻找可迁移机制的工程内化。

不适合：需要全面保存一个领域知识、法律/安全审计要求逐项穷尽、或来源本身就是最终研究对象。此时应回到完整的分片—核查—综合产线，而不是强行使用漏斗。
