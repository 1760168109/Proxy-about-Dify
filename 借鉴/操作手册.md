# lan 参考仓库集漏斗内化 · 操作手册

> **入口**：通用方法见 [`漏斗内化.md`](漏斗内化.md)，项目尺度与开放来源集见 [`本地代理·借鉴镜面.md`](本地代理·借鉴镜面.md)。
>
> **产物**：不再按仓建立 α／β／γ。整轮只保留 `概览、精研、综合` 三份正式文件。

## 一、阶段总览

```text
阶段 1 · 来源集概览
        ├─ 逐仓扫描（ultra）
        │      ↓ 明确停点；柳生切换档位
        └─ 批次归并（max）
               ↓ 若尚有下一批，切回 ultra；末批才形成最终 T-xx
        ↓ 停点：柳生选定精研题目
阶段 2 · 按题精确内化（max）
        ↓
阶段 3 · 新鲜上下文复核（max；直接修订同一份精研文件）
        ↓
阶段 4 · 综合融会（max）
        ↓ 停点：柳生裁决并写回同一份综合文件
结束；实施另行启动
```

全程四阶段。来源盘点并入概览开头，不再单设登记任务；文档数量固定为三份，不随来源数量或精研题目数增长。阶段 1 可以按本轮施行计划分批概览，但所有批次仍属于同一轮阶段 1。若施行计划指定混合档位，每批都在两个回合中完成：`ultra` 只负责可独立并行的逐仓取证，`max` 负责统一归并与裁决。

## 三、阶段 1 · 来源集概览扫描

### 目标

用一轮低成本扫描建立实际来源集的地形，选出少量跨来源精研题目。此轮可以分批执行；每批不深读完整仓库、不诊断 lan 实现、不生成方案。

### 分批硬约束

若本轮施行计划把来源集分为多批：

1. 所有批次共用唯一的 `01-概览与选题.md`，不得按批次另建正式文件；
2. 非末批只落盘本批来源卡、未读边界、暂定候选和待后批校正项；最终精研选题保持锁定；
3. `01` 必须显式记录所有计划批次的完成状态，不得把“当前已下载／已扫描的来源”误写成总来源集；
4. 只有计划中的末批扫描完成后，才能跨批归并、形成最终 `T-xx` 并停在柳生选题点；
5. 批次只约束概览的读取与落盘边界，不把阶段 2、3、4 拆成多轮。
6. 若施行计划区分 `ultra` 扫描与 `max` 归并，两者必须分属不同回合，并在前者完成后停下等待柳生切换档位；不得在一个回合内假定档位已经静默改变。
7. 并行工作流或子代理只回报统一格式的来源证据；共享的 `01` 始终由主代理单点写入，不得并行编辑。

本轮若存在 `借鉴\内化施行计划.md`，其仓库分配、当前批次与停点是阶段 1 的直接执行契约。

### 逐仓扫描提示词（`ultra`）

```text

请完整读取当前任务的 AGENTS.md 指令，以及：
1. 借鉴\漏斗内化.md
2. 借鉴\本地代理·借鉴镜面.md
3. 借鉴\操作手册.md
4. 借鉴\内化施行计划.md（若存在）

只扫描施行计划明确指定的当前批次；不得把当前批次当成总来源集。把各仓作为独立只读工作流，统一使用《漏斗内化》的来源概览卡：
- 每个来源只读到足以确认定位、主控制链、与 lan 的交点、候选锚点及未读边界；
- 不逐文件通读，不写单仓报告，不因高星或预期镜头强行选题；
- 每个来源给出“精研 / 旁证 / 排除”，并说明依据；
- 只在必要时用 Context7 作项目文档导航，正式锚点仍来自当前解压原件；
- 不读取 .env、岚.yml、请求日志正文或用户数据；
- 不修改本地代理和参考仓库，不读取 lan 目标实现，不进入精研；
- 子代理只回报结构化证据，不写共享文件；主代理检查后单点写入来源卡。

只写：借鉴\内化结果\01-概览与选题.md

本回合只写当前批各仓来源卡、实际已读锚点、未读边界与单仓建议，不作批次或跨批归并，不分配 P-Axx / T-xx。完成后呈报扫描是否完整与最大证据缺口，明确请我切换到 max，然后停止；不创建 02。
```

提示词中的“启用 ultra”是协作标签；实际档位由柳生在 Codex 界面选择。

- 若当前不是末批，只形成临时 P-Axx、本批重合/矛盾/旁证/排除与后批校正问题，最终选题保持锁定；
- 若当前是末批，才跨全部来源校正、消重与反证，形成最终 T-xx；
- 只在需要裁决事实冲突时复看既有锚点，不扩成新一轮逐仓扫描；
- 不读取秘密，不修改任何实现或配置，不创建 02。

只修订同一份 01。服从施行计划给当前归并回合规定的呈报内容与停点，完成后停止。

## 四、阶段 2 · 按题精确内化

### 执行方式

执行档位为 `max`。

一个精研题目一个新任务，**按顺序执行，不并行写同一文件**。每个任务读取现有 `02`，只新增或修订自己的 `T-xx` 节；文件不存在时由第一题建立。

这样对话数随最终题目数增长，正式文件数不增长。若十来个来源最终只选出 3 个题目，就只做 3 次精研，而不是按来源数量制造产线。

### 启动提示词

```text
阿岚，我已在 Codex 界面启用 max。执行 lan 参考仓库集漏斗内化的精研题目 {T-ID}「{题目名称}」。

工作区：C:\Users\杨\Desktop\Key chain\AI 装置\本地代理

请完整读取当前任务的 AGENTS.md 指令，以及：
1. 借鉴\漏斗内化.md
2. 借鉴\本地代理·借鉴镜面.md
3. 借鉴\内化结果\01-概览与选题.md 中 {T-ID} 的最终选题
4. 借鉴\内化结果\02-精研与映射.md（若已存在，保护其他题目）

按《漏斗内化》的双端顺序进行精研：
- 先读主来源的候选实现、失败路径和相邻测试，形成来源事实；
- 再读 lan 对应控制链，形成目标事实、已有保护与当前负担；
- 只在能改变判断时读取旁证来源；
- 明确两端是否同类、拟移除、新增代价、分量纲净变化、明确不搬、验证与回滚；
- 凡触及删除、替换、合并或短路，必须完成保护机制门；
- 达到自适应停止条件即停，不扩成完整仓库调研；
- 不读取秘密，不连接 Dify/Claude Code，不修改任何实现或配置。

只写或修订：借鉴\内化结果\02-精研与映射.md 中 {T-ID} 一节。

完成后呈报暂定结论、最强证据、最强反例、净变化和仍未证之处，然后停止，不进入下一题或综合。
```

### 精研期间的判断尺度

| 情形 | 处置 |
| --- | --- |
| 来源机制清楚且目标存在对应负担 | 深入双端证据 |
| 目标已有更适配保护 | 尽快形成“保持现状”并停止 |
| 静态阅读已无法回答 | 建外部证据门，不继续堆代码阅读 |
| 必须搬入整个平台才能采用 | 原则上排除，除非另有目标需求 |
| 新抽象没有明确删除旧责任 | 不得写作净精简 |
| 某来源未贡献精研机制 | 正常，不补数量 |

## 五、阶段 3 · 新鲜上下文复核

所有精研题目完成后，以 `max` 新开一个任务。复核直接修订 `02`，不创建“核查报告”。

### 启动提示词

```text
阿岚，我已在 Codex 界面启用 max。启动 lan 参考仓库集漏斗内化的阶段 3「精研复核」。

请完整读取当前任务的 AGENTS.md 指令，以及：
1. 借鉴\漏斗内化.md
2. 借鉴\本地代理·借鉴镜面.md
3. 借鉴\内化结果\01-概览与选题.md
4. 借鉴\内化结果\02-精研与映射.md

在新鲜上下文中逐题复核事实偏差、提取偏差和结构缺陷：
- 抽查每题最承重的来源锚点与目标锚点；
- 检查两端是否真为同类机制；
- 检查数字、枚举、状态、失败路径与证据等级；
- 检查是否隐藏新增依赖/状态、重复计重或把“更短”当“更好”；
- 删除/替换项若保护链不完整，收窄为保持或待证；
- 保留最强异议与真正未决边界。

直接修订 02-精研与映射.md；不另建核查文件，不修改任何实现。完成后呈报被翻转、收窄、维持和转待证的题目，然后停下。
```

## 六、阶段 4 · 综合融会

执行档位为 `max`。

### 启动提示词

```text
阿岚，我已在 Codex 界面启用 max。启动 lan 参考仓库集漏斗内化的阶段 4「综合融会」。

请完整读取当前任务的 AGENTS.md 指令，以及：
1. 借鉴\漏斗内化.md
2. 借鉴\本地代理·借鉴镜面.md
3. 借鉴\内化结果\01-概览与选题.md
4. 已复核的借鉴\内化结果\02-精研与映射.md

按 lan 的目标不变量和失败域综合，不按仓库拼接：
- 合并重合与互补机制，分开同主题不同失败域；
- 同一目标锚点被多个来源照见不得重复计重；
- 运行体积、代码、状态、请求、依赖和验证负担分别呈现；
- 每项采用、保持或排除都保留来源追溯、保护边界和净变化；
- 产品/架构取舍编号为 D-xx，外部运行事实编号为 E-xx；
- 只纳入已精研题目，不夹带概览中未深证的普通 TODO；
- 给出实施顺序、独立支线、验证、退出与回滚，但不修改代码或外部状态。

只写：借鉴\内化结果\03-综合内化方案.md

完成后向我呈报核心采用/保持/排除、最大净收益、最高误伤风险、D-xx 与 E-xx，然后停在裁决点，不实施。
```

### 柳生裁决回复

```text
阿岚，以下是我对综合方案的裁决：

- D-01：选择……；理由是……
- D-02：采纳你的建议。
- D-03：延期，不阻塞独立治理。

E-xx 不以我的偏好代替证据：
- E-01：保留为相应实施批次的进入门。

请把决定写回 03-综合内化方案.md，更新实施顺序与就绪度后停止，不修改实现。
```

写回完成即代表本轮内化结束。

## 七、源码清退

内化结束后，三份结果文件已经承接需要保留的认识；参考源码不是永久档案。

- ZIP 在解压成功后即可删除；
- `03` 定稿后，可以直接清退整个 `借鉴\仓库\`；
- 若马上实施高风险删除或替换，可暂留被采用结论直接引用的少数仓库，验证完成后再删；
- 清退后保留 `漏斗内化.md`、项目镜面、操作手册与 `内化结果\01–03`；
- 日后极少数需要重访的来源，依据仓库名／URL与 `02` 中的相对路径、符号重新下载即可。

仓库目录已被本项目 `.gitignore` 忽略，清退不会影响方法文档与内化结果。

## 九、偏航纠正

| 偏航 | 纠正语 |
| --- | --- |
| 概览开始完整通读仓库 | “当前只需可靠选题；请在定位候选锚点与未读边界后停止下探。” |
| `ultra` 扫描顺手作跨仓归并 | “当前只写来源卡与未读边界；请停在模式切换点，由 max 回合统一归并。” |
| 子代理并行编辑 `01` | “共享文件只由主代理单点写入；子代理只回报结构化证据。” |
| 每个来源强行选一个题 | “精研单位是机制，不是仓库；允许任一来源只作旁证或退出。” |
| 精研扩成仓库报告 | “回到 T-xx 的可裁断问题，证据足够改变决策即停止。” |
| 用来源数量投票 | “同一目标锚点只算一份目标事实，请保留不同机制侧面。” |
| 新抽象只增不减 | “列出被删除的旧责任；没有实际移除就不能写净精简。” |
| 又创建新报告 | “正式产物固定三份；请修订对应的 01、02 或 03。” |
| 静态结论冒充真实链路 | “将它转为 E-xx；不以继续读代码代替外部证据。” |
| 综合后开始改代码 | “03 定稿是本轮终点；实施必须另行启动。” |
