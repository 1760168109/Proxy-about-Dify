## 一、项目身份

- 目标根目录：`C:\Users\杨\Desktop\Key chain\AI 装置\本地代理`
- 项目名称：lan 本地代理
- 项目类别：面向 Claude Code 的本地 LLM 网关与协议适配器
- 结果目录：`C:\Users\杨\Desktop\Key chain\AI 装置\本地代理\借鉴\内化结果`

- 任务目标：在不削弱协议忠实性与历史故障保护的前提下，寻找可证明的净精简
- 本轮边界：只产分析与方案，不改代码、测试、配置、Dify 或真实数据

### 北极星

在 Dify 额度约束内，工具执行留在 Claude Code；lan 忠实转译、同层批量、纯化上下文，并只通过显式契约消除可证明多余的上游调用。不得用猜测短路、静默裁剪或伪造成功换取表面上的更小、更快。

### 当前主链

```text
Claude Code
  → main /v1/messages
  → plan 判枪
  → terminal 严格本地裁决
  → parse 消息与上下文
  → outbound 组装、边界与线缆
  → dify 上游流
  → answer 转译与收尾
  → Claude Code 执行工具并回传 tool_result

旁路：sessions / agent_bridge / cache / singleflight / meter / log / protocol
```

lan 不是通用网络代理、商业多租户网关、工具执行器或多 provider 管理平台；参考仓中的相关平台能力默认不搬。

| 代码/分支 | 统一事实定义、减少重复扫描、收窄模块责任 | 只减少文件数或造一个全能通用层 |
| 状态/生命周期 | 合并同寿命状态、统一容量与 TTL | 混合主/子会话或改成无界内存 |
| 请求/延迟 | 消除已证明的重复调用、移出非关键后处理 | 猜成功、误取消共享任务、擅改响应形态 |
| 依赖/部署 | 保持 Dify provider 边界而不平台化 | 为局部机制搬入数据库、Redis、K8s、ClickHouse 或后台 |
| 验证/排障 | 以不变量组织证据、缩短定位链 | 删除反事实测试或混写证据等级 |

## 三、不可静默损伤的边界

以下是精研删除、替换或合并建议的调查门，不等于冻结当前实现：

1. **协议形态**：`body.stream` 优先、`Accept` 次之、否则 JSON；Dify 恒流式不改变对 CC 契约。
2. **枪型与会话**：`kind`、`route`、`attachment_scope` 不互推；旁路与子代理不得污染主 CID。
3. **工具真实成功**：坏工具块可见，不产半调用；terminal 仅在 session、tool id、批次与成功形态全部精确匹配时短路。
4. **上下文无损**：正文只归一个逻辑载体，空串覆盖旧变量；Unicode 线缆与编号槽可逆，越界明确拒绝而不裁剪。
5. **重试与计费**：同体非流重试合并为一个上游任务；单个等待者断开不取消共享任务；Dify 接受即计费。
6. **身份与持久状态**：子代理身份来自 hook 与验签 marker，主/子 CID 分域；失败枪不绑定成功会话，状态有界且原子写。
7. **交付观测**：Dify 上游、lan 转译器、ASGI 发送是三个不同事实；任何一层都不能单独证明 CC 已消费。
8. **日志诊断**：可降低正文保存量，但必须保留足以定位路由、上游、转译和发送边界的证据，并继续遮蔽秘密。

凡触及上述边界，精研卡须写清：

```text
触发条件 → 所防故障 → 外部行为 → 当前实现 → 验证锚点 → 等价替代 → 未证部分
```

## 四、本轮查找镜头

| 镜头 | 概览要寻找什么 |
| --- | --- |
| 日志与观测 | 成功/失败/拒绝/抽样分级、按字节保留、压缩、异步后处理、阶段指标 |
| 薄入口与生命周期 | handler 如何只编排，不吞入转换、provider 与观测细节 |
| 请求事实索引 | 是否以只读 IR/索引统一 trailing user、tools、文件状态等重复判断 |
| 转换器边界 | request/response/stream translator 与 provider executor 怎样分工 |
| 显式流状态 | text、thinking、tool、usage、错误与 finalize 如何统一收束 |
| Dify provider | 参数发现、上传、调用、事件流与协议转换哪些可收敛，哪些必须分层 |
| 状态与并发 | 哪些状态同寿命可合并，哪些命名空间和 fence 绝不能混合 |
| 测试组织 | 怎样按不变量保留故障证明，同时减少重复 fixture 与断言口径 |

初始高价值问题只有四个，概览可以改写、合并或全部否决：

```text
Q1 日志治理能否直接降低运行体积而保留三层取证？
Q2 薄 handler + DifyProvider 能否缩短 main 的责任链？
Q3 只读请求索引/最小 IR 能否消除重复扫描而不形成新巨层？
Q4 显式 stream state 能否收敛 answer 的状态与终态处理？
```

### ZIP 使用与源码清退

- 每个 ZIP 解压为 `借鉴\仓库\` 下的一个直接子目录，保留 GitHub 默认目录名即可；
- ZIP 解压成功后可以立即删除，不要求保留下载日期、tag、commit 或 SHA-256；
- 精研时在 `02` 保存真正使用过的相对路径、符号与测试名，作为最小证据锚；
- `03` 定稿后，`借鉴\仓库\` 可以整体清退；若马上实施高风险改造，只需暂留被采用结论直接引用的少数来源；
- 不把多个仓库的内容合并到同一目录。

## 六、事实源与读取边界

### 目标端优先级

1. 当前代码与当前测试；
2. `架构.md`、`经验.md`、`README.md` 中仍与代码一致的契约；
3. 经授权取得的运行轨迹；
4. 历史报告与参考来源对 lan 的推测。

### 默认可读

- lan 根部 `.py`、`README.md`、`架构.md`、`经验.md`、`.env.example` 与 `tests/`；
- `data/` 的文件名、数量、体量与有界状态形状统计；
- 已登记参考仓库的代码、测试、公开文档与非秘密配置。

### 默认不读／不做

- `.env`、`岚.yml`、请求日志正文、用户 transcript、真实凭据与私有数据；
- 依赖目录、构建缓存和与本轮无关的大体量产物；
- 不连接 Dify 或 Claude Code，不改变外部状态；
- 不修改目标与参考仓库实现；
- 分析阶段不以运行测试为默认完成条件，现有测试可作为静态锚点。

需要真实 Dify 多轮、CC 消费、长任务、图片或部署证据时，进入 `03` 的外部证据门，不用静态阅读补齐。
